# ADR 0005: 리프레시 토큰 저장과 무효화

## 상태
채택

## 배경
PRD에 따라 로그아웃하면 리프레시 토큰을 무효화해야 한다. JWT만으로는 만료 전에 무효화할 수 없어서 서버에 상태를 저장해야 한다.

## 선택지
- DB 저장
- Redis 저장

## 결정
리프레시 토큰을 DB 테이블에 원문이 아닌 해시값으로 저장한다. 로그아웃하면 해당 행을 삭제한다.
리프레시 토큰마다 암호학적으로 안전한 무작위 `jti`를 넣고, DB 레코드에 `jti`를 함께 저장한다.
토큰 해시는 SHA-256으로 만든다.
로그인할 때마다 리프레시 토큰 행을 추가한다. 여러 기기에서 동시에 로그인할 수 있다.

## 이유
- Redis 같은 별도 저장소 없이 무효화할 수 있다.
- DB가 유출돼도 해시값만으로는 토큰을 쓸 수 없다.
- 리프레시 토큰은 무작위 값을 담고 있어 bcrypt처럼 느린 해시가 필요 없다. 또 JWT 문자열은 72바이트를 넘어 bcrypt 5.0에서는 `ValueError`가 난다(ADR 0002).
- HS256 서명은 같은 내용이면 같은 토큰을 만든다. `jti`가 없으면 같은 사용자에게 같은 초에 발급된 토큰이 서로 같아질 수 있다. `jti`로 발급마다 다른 토큰이 되게 한다.

## 영향
- 재발급과 로그아웃 요청마다 DB를 조회한다.
- 만료된 토큰 행이 DB에 남는다.

## 향후 개선
- 만료된 리프레시 토큰 행을 정리하는 방법
