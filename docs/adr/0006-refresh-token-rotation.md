# ADR 0006: 리프레시 토큰 교체(rotation)

## 상태
채택

## 배경
토큰 재발급 시 리프레시 토큰을 그대로 둘지, 새로 발급할지 정해야 한다.

## 선택지
- 교체함: 재발급 시 새 리프레시 토큰을 발급하고 기존 토큰을 무효화
- 교체 안 함: 재발급 시 기존 리프레시 토큰을 유지

## 결정
재발급할 때 새 리프레시 토큰을 발급한다. 기존 토큰 무효화와 새 토큰 저장을 한 트랜잭션으로 처리한다.
새 리프레시 토큰에는 새 무작위 `jti`를 넣는다(ADR 0005).
기존 행을 삭제한 행 수가 1일 때만 새 토큰을 발급한다. 같은 토큰으로 동시에 들어온 다른 요청은 `INVALID_TOKEN`으로 응답한다.
기존 행 삭제는 `id`가 아니라 `jti`를 조건으로 한다.

## 이유
- 한 번 쓴 리프레시 토큰은 다시 쓸 수 없으므로, 탈취된 토큰의 재사용을 막는다.
- 한 트랜잭션으로 묶어 둘 중 하나만 성공하는 상태를 막는다.
- 삭제한 행 수를 확인해, 동시 요청으로 토큰 하나에 세션이 두 개 생기는 것을 막는다.
- SQLite는 가장 큰 `id`의 행이 지워지면 그 `id`를 새 행에 다시 줄 수 있다. `id`로 지우면 다른 요청이 새로 저장한 행을 지워 삭제 행 수가 1이 되므로 동시 재발급 방지가 깨진다. 발급마다 새로 만들어 재사용되지 않는 `jti`로 지운다.
- HS256 서명은 같은 내용이면 같은 토큰을 만든다. `jti`가 없으면 같은 초에 재발급될 때 새 토큰이 기존 토큰과 같아져 교체가 무의미해진다.

## 영향
- 재발급 응답에 액세스 토큰과 리프레시 토큰을 모두 담는다.
- 클라이언트는 재발급 후 새 리프레시 토큰으로 바꿔 저장해야 한다.

## 향후 개선
- 이미 무효화된 토큰이 다시 들어왔을 때 해당 사용자의 다른 리프레시 토큰까지 무효화하는 처리
