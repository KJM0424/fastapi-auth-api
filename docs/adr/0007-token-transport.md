# ADR 0007: 토큰 전달 방식

## 상태
채택

## 배경
클라이언트가 토큰을 서버에 보내는 방식을 정해야 한다.

## 선택지
- Authorization 헤더 Bearer 방식
- 쿠키

## 결정
Authorization 헤더에 `Bearer <토큰>` 형식으로 보낸다.
이 결정은 액세스 토큰에 대한 것이고, 리프레시 토큰은 요청 본문으로 받는다.

## 이유
- 프론트엔드 화면이 없어서 쿠키를 쓸 이유가 없다.
- Swagger UI의 Authorize 기능으로 바로 테스트할 수 있다.
- 헤더를 액세스 토큰 전용으로 두면 헤더로 들어온 토큰의 종류를 구분할 필요가 없다.
- OAuth2 표준도 리프레시 토큰을 요청 본문으로 보낸다([RFC 6749 6절](https://datatracker.ietf.org/doc/html/rfc6749#section-6)). 표준은 `application/x-www-form-urlencoded` 형식이지만, 이 프로젝트는 다른 엔드포인트와 맞춰 JSON 본문을 쓴다.

## 영향
- 로그인과 재발급 응답 본문으로 토큰을 반환한다.
- 토큰 재발급과 로그아웃은 요청 본문 `{"refresh_token": "..."}`으로 리프레시 토큰을 받는다.
- 쿠키를 쓰지 않으므로 CSRF 대응이 필요 없다.
