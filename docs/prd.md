# PRD

## 목적
FastAPI로 회원가입, 로그인, JWT 인증 API를 만든다.
하루 안에 완성하는 학습·포트폴리오용 프로젝트다.

## 사용자
- API를 호출하는 클라이언트 개발자. 회원가입, 로그인, 토큰 관리, 내 정보 조회를 HTTP로 호출한다.
- 포트폴리오를 보는 사람. 인증 흐름의 구현과 문서를 확인한다.

## 기능 목록
| 기능 | 설명 | 필요한 토큰 |
|---|---|---|
| 회원가입 | 이메일과 비밀번호로 계정을 만든다. 이미 가입된 이메일이면 거부한다. | 없음 |
| 로그인 | 이메일과 비밀번호가 맞으면 액세스 토큰과 리프레시 토큰을 발급한다. | 없음 |
| 토큰 재발급 | 유효한 리프레시 토큰으로 새 액세스 토큰을 발급한다. | 리프레시 토큰 |
| 로그아웃 | 리프레시 토큰을 무효화한다. 무효화된 토큰으로는 재발급할 수 없다. | 리프레시 토큰 |
| 내 정보 조회 | 로그인한 사용자 본인의 정보를 반환한다. | 액세스 토큰 |

## 제외 범위
- 소셜 로그인
- 이메일 인증
- 비밀번호 찾기
- 관리자 기능
- 프론트엔드 화면

## 비기능 요구사항
- 비밀번호는 평문으로 저장하지 않는다.
- 응답에 비밀번호나 비밀번호 해시를 포함하지 않는다.
- 토큰 서명 키 같은 비밀 값은 코드에 넣지 않고 환경 변수로 관리한다.
- 이메일 형식과 비밀번호 조건(ADR에서 결정)을 서버에서 검증한다.
- 오류 응답은 일관된 형식으로 반환하고, 상태 코드는 API 스펙에 정한 대로 따른다.
- 각 기능의 정상 흐름과 주요 실패 흐름을 자동화 테스트로 확인한다.

## ADR에서 결정할 항목
- 데이터베이스 종류
- 비밀번호 해싱 알고리즘과 라이브러리
- JWT 서명 알고리즘과 라이브러리
- 액세스 토큰과 리프레시 토큰의 만료 시간
- 리프레시 토큰 저장 및 무효화 방식
- 토큰 재발급 시 리프레시 토큰 교체(rotation) 여부
- 클라이언트에 토큰을 전달하는 방식(응답 본문, 쿠키 등)
- 비밀번호 조건(최소 길이, 문자 구성)
- 오류 응답 형식

## 완료 기준
- 기능 목록의 5개 기능이 API로 동작한다.
- 비기능 요구사항을 모두 충족한다.
- 자동화 테스트가 모두 통과한다.
- `docs/adr/`에 위 결정 항목이 기록되어 있다.
- `docs/api-spec.md`에 모든 엔드포인트가 문서화되어 있다.
- code-reviewer 리뷰를 거쳐 main에 머지된다.
